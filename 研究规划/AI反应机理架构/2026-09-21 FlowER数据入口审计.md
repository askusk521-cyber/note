# FlowER 机理数据入口

日期：2026-09-22。FlowER 是当前最接近“产品无关事件/路径提案”数据合同的公开入口，但代码归档和训练数据是分开的。

## 已核实内容

- Zenodo `15786107` 的 FlowER v2 代码包只有训练脚本、模型实现和 README，不含 `data/` 或 checkpoint 数据。
- README 指向 Figshare `10.6084/m9.figshare.28359407.v3`。DataCite 元数据显示总大小约 **682,451,909 bytes**，包含 `flower_dataset` 和修订版 `flower_new_dataset`。
- 每行格式是 `atom-mapped reactants>>products|overall-reaction-index`，记录粒度是 elementary step；相同 overall reaction index 的步骤组成一条路径/网络。
- 已实现 [`src/mechai/data/flower.py`](../src/mechai/data/flower.py) 的流式合同审计：严格解析行格式，保留空行/行号和非连续 sequence index，按 overall-reaction 编号报告跨 split 泄漏；可选 RDKit 检查 atom-map/元素、显式 H、总电荷和图键差异，但不推断步序、多重度或隐含氢身份。对应测试为 [`tests/test_flower.py`](../tests/test_flower.py)。

## 为什么它比 USPTO-15K 更适合下一阶段

它直接提供逐步图变化和 overall-reaction 分组，可以把产品只用于训练标签与最终评估，推理只输入当前反应物状态。这比只有净键编辑的 USPTO-15K 更接近 FlowER 约束和“候选事件→路径”的问题。

## 仍然不能过度解释

- 图级步骤不是三维过渡态，也不是独立 DFT/IRC 认证。
- 数据没有当前目标所需的显式水环境、pH、溶剂构象和完整微观态合同。
- overall reaction 的已报道产物路径不等于全部物理竞争路径；未出现的路径不能当作负例。
- 必须按 overall-reaction index 重建组留出，不能按 elementary step 随机拆分。

当前 Figshare API 和下载入口返回 HTTP 403，因此本轮没有把数据文件当作已下载，也没有训练模型。取得数据后首先用上述审计器检查 atom-map 守恒、电荷/多重度字段、路径长度和组泄漏，再建立只读反应物的净编辑/下一步事件基线；`sequence_idx` 只作为 overall-reaction 分组键，不当作物理步序。
