## 2. n2运行规则

2026-09-21已通过只读检查确认：SSH别名为`n2`，主机名为`node2`，用户目录为`/home/lhshen`；Slurm分区为`main`，登记资源为`gpu:pro6000:4`。这不表示四张卡都空闲，也不表示已执行GPU验证。

- 本项目真实GPU推理、训练、测试、性能分析与基准均在n2通过Slurm运行；初次调试申请1张卡。
- n2申请参数为`--partition=main --gres=gpu:pro6000:1`；每个作业必须显式指定有限时长。短GPU检查采用10分钟上限，正式实验按配置给出预算。
- 保留Slurm分配的`CUDA_VISIBLE_DEVICES`，不得清除或覆盖它以绕过调度。记录job ID及实际分配资源。
- 本机用于编辑、轻量CPU数据检查和单元测试。本机5090若将来另有授权使用，仍遵守用户原有的`main`/`gpu:5090:1`规则；该型号参数不能套用到n2。
- `hosts/n2.json`记录主机路径和调度约定；它目前是声明性配置，尚无提交器读取并强制执行。

供后续提交器采用的n2作业前缀如下；本轮没有运行该作业：

```bash
srun --partition=main --gres=gpu:pro6000:1 --nodes=1 --ntasks=1 \
  --time=00:10:00 <实验命令及参数>
```

生产逻辑放在Python模块中；notebook仅作探索或绘图，不作为唯一可复现实验入口。公共接口、非显然的化学假设和后端限制应有docstring或必要注释。

起步基线环境先匹配官方UniTS-Gen依赖，在n2建立项目独立环境并锁定实际可运行的版本。不改动共享环境，不预先猜测PyTorch、CUDA、RDKit等版本。每个run记录Python、框架、关键几何/化学依赖及实际GPU环境。正式运行入口要从主机配置或命令行解析路径；不得在模型与数据逻辑中写死个人目录。

## 4. 数据管理和科学边界

- 原始数据只读，处理后的数据另存。每个来源登记版本/DOI、URL、许可证、下载时间、文件SHA256、标签理论层次及预处理版本。未核实许可证时不得代作者重新公开分发。
- 暂定主数据为UniTS-Lib，溶剂诊断数据为Kingfisher。其他数据集仅在标签需求明确时引入。
- 数据合同明确原子顺序、电荷、自旋多重度、坐标单位、能量/力单位、来源与验证级别。未知值明确缺失，不默认中性或已验证。
- 固定训练/验证/测试记录ID与分组依据；同一反应的构象、路径帧和重复记录按适用组绑定。官方Formula-OOS复现单独保留原划分，不能自行换划分后继续称为官方复现。
- 参考TS提取的图/中心条件标记为oracle条件；独立输入评价另行报告。几何接近公开TS不能算作新候选已通过DFT验证。
- 小型清单、处理代码、split与结果摘要进入版本管理；原始数据、处理缓存、模型权重和完整run目录不进入普通Git历史。

## 5. 每次实验必须留下什么

run ID采用`YYYYMMDD-HHMMSS_E阶段_短描述_s种子`，时间按Asia/Shanghai记录。开始运行时创建新目录，不覆盖旧run；恢复运行需记录`resumed_from`和使用的checkpoint。

每个`runs/<run_id>/`至少保存：

| 文件或内容 | 用途 |
|---|---|
| `run.json` | 问题/假设、运行状态、开始结束时间、主机、job ID、随机种子与候选预算 |
| `config.resolved.json` | 展开默认值后的完整实际配置，包括主机与数据路径 |
| `code.json` | Git commit或源码快照ID、文件哈希清单、官方代码版本及本地改动 |
| `data.json` | 数据版本、split ID/哈希、实际评价记录ID与标签来源 |
| `environment.txt` | 实际依赖版本与运行环境 |
| `command.txt`、`stdout.log`、`stderr.log` | 可复现命令及日志 |
| `metrics.json`、`predictions/` | 汇总指标、逐样本候选和失败原因；不只保留最好结果 |

没有Git提交时可以使用固定文件集的SHA256清单和完整源码快照作为`code_id`；不能把`unknown`版本当作可复现记录。建立Git后优先用commit标识，若有未提交改动，须同时保存包含新增文件在内的完整快照，不能只记commit。

首次调试允许单种子；用于架构判断的比较应采用匹配的数据、输入条件、种子和候选预算，原则上复用至少3个种子，无法完成时明确只是先导证据。区分单候选与best-of-k指标，记录样本数、独立反应组数与计算开销。

## 6. 版本管理、上游代码与同步

代码仓库范围暂定为`reaction_pilot/`，当前尚未初始化；本规范不代表已经创建远程仓库或提交代码。首次正式开发时建立本地Git，GitHub仓库可随后确定，不阻塞本地开发。

代码按固定快照从本机部署到n2，先检查待同步清单；数据、环境、权重与运行输出各自管理，不随源码覆盖。同步不能删除既有实验。将小型结果摘要回收到本机`reports/`，研究结论同步到Obsidian；完整轨迹与checkpoint保留在n2并记录位置和校验和。

所有Git提交、GitHub评论和PR均遵守用户的AI署名要求：操作前读取`codex --version`及`~/.codex/config.toml`中的`model`、`model_reasoning_effort`，不能猜测。无法核实这些值时停止提交/发布并说明缺失项。具体署名格式见`AGENTS.md`。
