# Model v0：保留全原子的条件噪声残差

更新：2026-09-21。状态：**架构代码、CPU性质测试、真实官方模型的零残差GPU前向回归及32步短训练已完成；尚未证明几何质量改善或科学收益。** 训练状态见`STATUS.md`。

## 1. 当前数据允许我们做什么

本模块遵循官方UniTS的坐标扩散和噪声预测目标，只增加一个条件残差。暂不加入flow、质子方案生成器、机器学习势或新量化计算。

根据项目已有字段清单、官方`units/data.py`及`notebook_process_dataset.ipynb`：

| 已知字段／来源 | 可用于什么 | 不能当作什么 |
|---|---|---|
| `inpt_orien`/`std_orien`参考TS坐标 | 官方噪声训练的干净目标；几何评估 | 独立观测的反应物水合环境 |
| `graph_feat`/`rdmol`、`chrg`、`mult` | 复用官方图条件及电子态信息 | 已独立从反应物获得的全部机理知识；图来源仍须随run记录 |
| `rct_idx` | 保持官方条件，单独注明参考TS派生的范围 | 未知水参与和质子接力的预测真值 |
| `modes`、频率 | 参考结构验证等级及后续有范围的分析 | 可直接视作完整IRC或通量标签 |
| 没有核实的独立反应物坐标／relay标签 | 保留接口和缺失状态 | 用参考TS坐标、注意力权重或元素识别自动伪造 |

全量4,391条记录的输入字段已审计，结果见`../reports/E0b/audit.json`。当前能够立即接入的模式，是**把官方已有的全图／位点嵌入用于一条几何相关的条件消息通路**。它没有增加独立实验信息，也不等于已经学习溶剂参与。若要研究真正的外部环境条件，必须先接入有来源的数据，并与新增信息量分开比较。

## 2. 实现与数学作用

文件为`src/mechai/models/conditioning.py`，核心类是`EquivariantEnvironmentResidual`。输入为当前带噪坐标 $X_t$、原有节点标量 $h_i$、扩散时刻 $t$、全原子mask，以及有来源的标量条件 $c_j$。

它对每个真实原子$i$接收所有已观测条件原子$j$的消息：

$$a_{ij}=f_\theta(h_i,h_j,c_j,t,\operatorname{RBF}(\|x_i-x_j\|)),$$
$$\widetilde{\delta\epsilon}_i=\frac{1}{n_i}\sum_{j\ne i}m_j a_{ij}\frac{x_i-x_j}{1+\|x_i-x_j\|},\qquad
\delta\epsilon_i=\widetilde{\delta\epsilon}_i-\operatorname{mean}_{\text{real atoms}}\widetilde{\delta\epsilon}.$$

最终预测是 $\hat\epsilon_{\rm official}+\delta\epsilon$。最后一层零初始化，所以初始残差严格为零。第一步readout得到梯度；readout离开零后，前面的条件编码层也能得到梯度。

- 所有真实原子始终保留为接收节点，输出形状与顺序不变；没有水选择／原子删除。
- `observed_mask=False`只表示该原子的额外条件缺失，不表示水不参与或不重要。
- `radial_scale`只设定距离基函数的尺度，不是删边半径；实现没有基于距离硬删除环境原子。
- 向量由标量系数与相对坐标构造，满足整体旋转、平移和原子置换对称性。分样本去均值保持官方零中心噪声空间；没有分别把水移回原点。
- 该简单残差不新增识别手性的几何机制，也不保证生成后立体化学正确；仍依靠官方图／几何骨干并独立评估手性。
- 系数$a_{ij}$不是注意力真值、参与水概率、反应通量或势能梯度。

为减少峰值内存，按接收原子分块构造全原子对；总计算仍为$O(N^2)$。这是便于验证的起步积木，不声称已验证大体系吞吐率。严格输入检查会读取张量值，不用于宣称最佳运行性能；任何提速均需先保持合同测试。

## 3. 可调用接口

```python
from mechai.models import (
    ConditionSource, EnvironmentCondition, EquivariantEnvironmentResidual,
)

residual = EquivariantEnvironmentResidual(node_dim=11, condition_dim=32)
condition = EnvironmentCondition(
    values=context,                    # [B, N, 32]，旋转不变的标量
    observed_mask=atom_mask,            # [B,N]或[B,N,1]，缺失不是删除
    source=ConditionSource.INPUT_GRAPH,
)
delta_eps = residual(noisy_xyz, fixed_node_features, t, atom_mask, condition)
eps_pred = official_eps + delta_eps
```

上面的11与32仅展示当前常见官方配置，实际维数必须由已加载配置/张量确定。输入坐标和全部浮点特征必须具有相同dtype/device，距离采用官方归一化后的单位。`condition=None`或全部条件缺失返回严格零残差；禁止把未知字段默认为零后仍标记“已观测”。

`ConditionSource.REFERENCE_TS_ORACLE`默认报错；只有构造时明确`allow_reference_ts_oracle=True`才允许单独报告的oracle诊断。该枚举是数据合同，无法自行证明输入来源；标量坐标误当特征也不能仅靠形状检查发现，数据审计仍不可省略。

## 4. 与官方UniTS接线

已核对的上游接口是固定revision `a7147021becc4e13887be2c756fefc8b5983f390`下：

- `units/en_diffusion.py::EnVariationalDiffusion.phi`调用`dynamics._forward(x,t,node_mask,edge_mask,context,batch)`。
- `x`含带噪坐标前三列与固定节点特征；`context`由现有分子图及反应位点编码器生成并padding。
- `units/hiegnn/model.py::HiEGNN_dynamics_DiffMM._forward`返回`[B,N,3]`坐标噪声。

`UniTSConditionedDynamics`实现相同`_forward`签名，不修改vendor代码：

```python
from mechai.models import EquivariantEnvironmentResidual, UniTSConditionedDynamics

# 先由官方代码加载原始checkpoint，得到diffusion；再包装，避免键名不匹配。
width = diffusion.context_node_nf
if diffusion.use_rct_cent:
    width += diffusion.rct_cent_node_nf
adapter = EquivariantEnvironmentResidual(
    node_dim=diffusion.in_node_nf,
    condition_dim=width,
)
base_parameter = next(diffusion.parameters())
adapter = adapter.to(device=base_parameter.device, dtype=base_parameter.dtype)
diffusion.dynamics = UniTSConditionedDynamics(diffusion.dynamics, adapter)
```

包装模式直接使用原`context`，其所有真实原子视为有条件；不会从干净TS读取附加几何。没有context或将`enabled=False`时，直接返回同一个基线预测张量。适配checkpoint增加`base_dynamics.`和`residual.`路径；应单独保存配置和权重，不覆盖官方checkpoint。

包装器不自动冻结参数。若做adapter-only训练，应由实验入口明确冻结**整个官方模型（包含外部图编码器）**，再启用适配器参数；只冻结`base_dynamics`不等于冻结整个基线。训练若包含官方dropout，还需明确其train/eval状态。EMA应在包装后构造，避免旧参数列表与新模型不一致。

首版保持原噪声schedule、loss、sampler、外层数据划分、输入原子、候选数一致。真实HiEGNN前向与零初始化回归已由Slurm job 1971验证：同一次调用的官方输出、包装输出与phi输出逐字节一致，残差恰零，RNG未额外消耗。它只验证一条输入的前向恒等性，不是改进模型的完整采样评价。

## 5. 最小可归因比较

1. 原始官方模型，复现当前split和checkpoint。
2. 包装但零初始化/关闭适配器，验证同随机数下预测保持一致。
3. 保留全部原子，训练几何相关图条件残差；只改变此通路。
4. 同参数预算、同训练设置下遮蔽/置乱附加条件作为诊断；遮蔽条件不删原子、不改变目标坐标。不要将另一套随机生成的微溶剂体系作为“同输入”对照。

由于当前通路重用官方已有图信息，任何收益首先解释为表示／参数适配收益，不能称为独立溶剂信息的收益。接入独立环境时另设匹配对照，并冻结其来源、单位、原子映射和可用性。

## 6. 本地验证与限制

依赖只有PyTorch；模块不导入UniTS、PyG、RDKit或任何量化程序。CPU测试入口：

```bash
PYTHONPATH=src python -m unittest discover -s tests -p test_conditioning.py -v
```

当前使用专属临时环境`/tmp/mechai-conditioning-cpu312`，Python 3.12.14、PyTorch 2.8.0+cpu。测试在明确的CPU张量上进行，未调用CUDA或更改`CUDA_VISIBLE_DEVICES`。

模型性质测试**14项通过**；另有9项GPU回归检查器的CPU对抗测试。真实GPU报告为`../reports/E1/adapter-check-v2.json`，检查协议见`ADAPTER_REGRESSION.md`。

测试检查实际模块的非零输出下旋转/平移/原子置换、不同padding和batch组成、mask和NaN隔离、零中心、条件改变、oracle防误用、零初始化、两步合成优化梯度、FP32包装和state_dict恢复。合成优化只检查可导通路，**不是化学训练或模型有效性结果**。

最初的跨调用逐位断言在job 1968失败，原始报告保留：官方baseline重放自身也有4.77e-7的FP32差异。v2通过捕获同一次底层调用严格验证恒等性，没有用放宽容差处理；跨调用差异仍单独报告。

这些检查不能证明混合精度兼容、吞吐改善、训练有效、目标反应泛化、真实水参与、DFT鞍点或IRC正确性。上述项目需分别产生证据；这份模块交付不替代它们。
